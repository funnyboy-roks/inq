# Contributing

Welcome!  If you're looking into contributing to inq, please review
these guidelines.

## Feature Requests

If you find that a feature is missing in inq, please [open an issue].
Not all feature requests will be accepted, but ideas are always welcome!

In order reduce duplicate issues, please first check for similar open
issues.

## Bug Reporting

If you find a bug or regression in inq, please [open an issue].

Please provide a minimal inq file and command needed to reproduce the
bug as that will make debugging significantly easier.

[open an issue]: https://github.com/funnyboy-roks/inq/issues/new/choose

## Pull Requests

If you wish to contribute code (or documentation) changes, please [open a
pull request] on GitHub.

[open a pull request]: https://github.com/funnyboy-roks/inq/compare

### Testing

It is important to ensure that all of our code works correctly, so we
want to have very thorough testing of all features.

Tests can be run using `cargo`, like with most other rust projects:

```sh
cargo test
```

#### `inq-lang`

Tests related to specific functions or similar implementations within
`inq-lang` should have unit tests for those functions.  Any language
items or native types should have integration tests.

#### `inq`

Unit tests in `inq` should be used for small functions or inq types.
Integration tests should be used for testing the command-line and
ensuring the correct behaviour.

When testing inq, we use `mockito` for mocking an http server and write
a small inq file to test the desired feature.

### Documentation

At the moment, documentation is fairly minimal.  If you run into any
documentation that is unclear or lacking detail, please feel free to
open a PR to update it!

We treat `inq-lang` like a standalone library, and as such, functions,
types, etc. should have documentation comments and doc tests, if
possible.

### Style

All code should be formatted using `rustfmt` and linted using `clippy`.  
If CI is complaining about format or linting, install either using
`rustup component add rustfmt` or `rustup component add clippy` and run
either `cargo fmt` or `cargo clippy`.

## LLM/"AI" Contributions

Inq is a tool made by humans for humans and as such, contributions must
not include content generated by large language models or any other
probabilistic tool, including but not limited to Copilot or ChatGPT.
This policy covers code, documentation, pull requests, issues, comments,
and any other contributions.

For more information on why we have this policy, Servo does a good job
of pointing out the various concerns:
<https://book.servo.org/contributing/getting-started#ai-contributions>
